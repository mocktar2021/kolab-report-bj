# Security review, October 2026

This is the review for Jira KRB-24, sub-tasks KRB-145 (RLS and policies), KRB-149 (service-role usage) and KRB-150 (AI endpoints). It lists what the database and the app allow today, where the tests stop, and what to fix. It changes no code.

## 1. Scope and method

- Date: 2026-10-14.
- Migrations reviewed: every file in `supabase/migrations`, from `20261013000000_initial_schema.sql` to `20261014140000_storage_cleanup.sql`. Two of them landed during the review: `20261014130000_close_cross_tenant_writes.sql` (commit 244d162, KRB-152) and `20261014140000_storage_cleanup.sql` (applied locally, not committed yet). Everything below describes the database with both applied.
- Live database: the local stack (`supabase_db_kolab-report-bj`, Postgres 17), read only. Queries were SELECTs on `pg_policies`, `pg_proc` (`prosecdef`, `proconfig`, `proacl`), `has_function_privilege`, `information_schema.role_table_grants` and `column_privileges`, `pg_class.relrowsecurity`, `pg_trigger`, `pg_default_acl`, `storage.buckets` and `pg_publication_tables`. Nothing was written.
- pgTAP: every file in `supabase/tests` was read. I did not run them, since they write inside their transactions.
- App code: every import of `createAdminClient`, every route under `src/app/api`, `src/lib/ai/**`, the server actions that call the database functions, and `src/lib/deliverables`, `src/lib/reports`, `src/lib/invitations`.
- Staging: only the Supabase advisor results passed on by the lead (section 8). I had no access to the staging database or its Auth settings.

Roles used below: owner and admin are the managers. "Expert" means an expert on a section assigned to them unless stated. "Non-member" is a signed-in user who is not in the workspace (another tenant, or no workspace at all). "Anon" is a visitor without a session.

## 5. Storage

- `deliverables`: private, 50 MB, MIME allowlist of 15 types including `image/svg+xml`. Select needs `private.can_read_deliverable(name)`: a row with that exact path, `uploaded_at` set, and the caller a member. Insert needs `private.can_upload_deliverable(name)`: the caller's own pending row, a section they can still edit, report open. No update or delete policy.
- `exports`: private, 50 MB, `.docx` and PDF only, no policies. Only the service role writes and signs.
- Signed URLs in the app:
  - `POST /api/deliverables/upload-url` signs the upload with the user client, so the insert policy is checked at signing. The URL works for 2 hours after that, even if the user loses the section. `POST /api/deliverables/[id]/complete` checks again and discards the file. A file never completed stays unreadable.
  - `GET /api/deliverables/[id]/file` signs for 60 seconds with the user client, with `download` set, except `?apercu` for images. SVGs are refused at `/complete` when `svgHasActiveContent` finds scripts, event handlers, an `xml-stylesheet` instruction or entity tricks. The signed URL is on the Supabase origin, not the app origin.
  - `checkStoredFile` signs for 60 seconds with the service role, for the caller's own pending row only.
  - `GET /api/exports/[id]` signs for 60 seconds with the service role after an RLS read of `report_exports` (managers only) and a check that the path starts with the row's `workspace_id`.
- Deleted rows: the uncommitted `20261014140000_storage_cleanup.sql` queues the path of every deleted `deliverables` and `report_exports` row in `private.storage_cleanup_queue`, cascades included. `GET /api/cron/storage-cleanup` (uncommitted, in the working tree) empties it once a day with the service role (F-17). `deliverables.storage_path` only has to start with `{workspace_id}/{section_id}/`, so a user can register any suffix and the app later removes that name with the service role. Storage removes objects by exact name, so a suffix like `../../` should not reach another workspace (to verify on the storage version in use).

## 7. AI endpoints (KRB-150)

There is one endpoint, `POST /api/ai/sections/[id]/draft`. `/api/ai/**` has nothing else.

- Authorization: session (`getCurrentUser`), RLS read of the section, `requireWorkspaceRole`, `canEditSection` (managers, or the assigned expert), report not final, template published and global or of the same workspace. `start_ai_generation` checks the template or rollout again. The draft only reaches the section through `accept_ai_generation`.
- Feature flag: `AI_DRAFTS_ENABLED` defaults to false; the mock provider is refused in production.
- Rate limit and budget: in `start_ai_generation`, under advisory locks: 30 requests an hour per user (`AI_RATE_LIMIT_PER_HOUR`, counted across workspaces, failures included), one running draft per section, 2 000 000 tokens a month per workspace (`AI_MONTHLY_TOKEN_BUDGET`), and one alert e-mail a day past `AI_DAILY_COST_ALERT_USD`. The alert does not stop anything, and a new workspace starts with a full budget (F-05).
- CSRF: the route reads the body as text and parses JSON whatever the content type (F-08).
- Prompt injection: `src/lib/ai/context/guards.ts` wraps deliverables and summaries in `<livrable>` and `<resume>` blocks, strips invisible characters and replaces any fake opening tag (`<`, full-width forms, entities) with `‹`. Section title, instructions, report title, description and workspace name go through the same cleaning and caps. The system prompt treats block content as data. The output is a schema-checked object; Markdown renders without raw HTML or images, and model links show as text.
- Data sent to the provider: section title and instructions, report title and description, workspace name, file names and the parsed text of the section's deliverables, within 60 000 input tokens. Overflow goes to the fast model for summaries. With `AI_REDACT_PII` on (default), e-mails, French and Benin phone numbers, IBANs, NIR and card numbers are masked before chunking, file names included. Names, postal addresses, dates of birth and company or tax ids (SIRET, IFU) are sent as is. When `AI_FALLBACK_PROVIDER` is set, the second provider gets the same data (F-16).
- Logging: the route logs truncation decisions (refs and counts, no text) and error messages. `ai_generations` keeps hashes of the input, not the input, and up to 200 000 characters of raw output, readable by managers and section editors. OpenTelemetry spans go out only with `AI_TRACING=true` and carry prompts and outputs only with `AI_TRACE_CONTENT=true`.
